# Explicit endpoint attempt recovery: software evidence and hardware handoff

Date: 2026-10-15. This report covers controlled software execution. It does not certify Harbor/Docker, SGLang, GPU loading, optimizer continuity, or multi-round hardware execution.

The real Hitch CLI submits to an already running daemon. A real bundled `model-call` process sends requests through the host model proxy to an authenticated controlled HTTP service. A deterministic host verifier seals canonical run records. The daemon test injects evaluation executors to run this CPU harness instead of Harbor; production rerun selection, endpoint admission, ordered control, public projection, usage aggregation, and canonical record storage remain exercised by their direct regression tests.

Observed sequence:

1. Deployment A receives `task:zero`, returns a valid observation with reward 0, then receives `task:repair` and returns HTTP 503.
2. Deployment B is registered after the daemon starts. Only the registering CLI receives its new environment credential. `--persist-credential` stores it in a private revision-scoped 0600 file; the existing daemon resolves it for its later upstream request.
3. Gear-style ordered pause fences a delayed old start. The test also injects a retained cancelled terminal projection after all old tasks have ended, then resumes with a strictly higher start sequence.
4. A fault is injected after the new endpoint attempt is frozen but before rerun submission persistence. Replaying the same stable rerun ID repairs only `task:repair` on B.
5. Replaying the completed command performs no new model request. The A zero-reward run remains byte-identical, both original request and plan files remain byte-identical, and task usage rises from 2 to 3 actual requests.

Additional tests reject competing binding admissions, changing a model/common condition/training binding, admitting a new incarnation while any later same-binding repair is active or ambiguous, and replacing a revision's credential. Public requests, results, attempt records, and task bindings contain neither the host secret nor connection URL. Missing token measurements remain unknown; cumulative request capture and all invalid/replacement publications are retained and deduplicated.

The API exposes `endpoint_evaluation_attempts=1` and `endpoint_host_credentials=1`. `eval rerun --endpoint-attempt-file` is limited to `--daemon --invalid --type candidate-restart`. The first release requires the original local task provider; local Docker tasks can still call a remote model. Independent remote-worker cross-incarnation repair stops explicitly and does not fall back to local execution. Hitch does not load, restart, retire, or stop model services. `eval inspect` exposes `pending_reruns`, including admitted-but-unsubmitted crash gaps and all later repairs. Gear can reconcile fully validated terminal canonical evidence using inspect calls alone before deciding whether an offline incarnation needs replacement; pending, partial, ambiguous, or mismatched evidence cannot establish completion.

Run the repository checks with its supported Python test environment and without unrelated host provider credentials. The regression entrypoints are `npm run typecheck`, `npm run build`, `npm run check:architecture`, `node dist/scripts/check-syntax.js`, `npm run docs:check`, `npm test`, and `npm run coverage`. The full regression run passed 911 of 928 tests with 17 explicit skips. The subsequent full coverage run, including the published schema test and terminal-observation support, passed 912 of 929 tests with the same 17 skips; coverage was 89.73% lines, 77.85% branches, and 89.96% functions. The final cancelled-admission-gap guard then passed all 53 directly affected endpoint/control/scheduler tests. Typecheck, build, syntax, documentation, and architecture checks passed (430 source files, 926 cross-module edges; 67 CLI command paths and 121 options per language). A disposable offline npm pack/install smoke passed against version 0.2.15, including new CLI flags/capabilities, immutable host credentials, attempt exports, required package files, and the published ordered-attempt schema, with zero model-network calls. A CPU fixture is not a hardware acceptance result.
